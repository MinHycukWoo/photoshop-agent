# 2단계: 연결 통로 만들기 (ping 테스트)

> 날짜: 2026-11-11 ~ 11-12 · 결과: ✅ **통과** (Inspector → MCP 서버 → WebSocket → 포토샵 → 응답 왕복 성공)

## 무엇을, 왜
Claude가 포토샵에 말을 걸려면 통로가 두 개 필요하다: **Claude ↔ MCP 서버**(stdio), **MCP 서버 ↔ 플러그인**(WebSocket).
생성 기능 없이 `ps_status` 도구 하나로 이 왕복이 되는지 먼저 확인했다. 3단계는 이 통로 위에 기능만 얹으면 된다.

```
[MCP Inspector / Claude Desktop]
      │  stdio (표준 입출력)
      ▼
[mcp-server]  ── ws://127.0.0.1:8765 (서버) ◀── [ps-plugin] (클라이언트) ── 포토샵 DOM / batchPlay
```

## 먼저 확인한 것 (추측 대신 근거)

| 질문 | 확인 결과 | 근거 |
|---|---|---|
| UXP는 WebSocket 서버를 열 수 있나? | **아니오, 클라이언트만.** 문서에 서버 API가 없음 | UXP WebSocket 레퍼런스 |
| manifest v5 network 권한 형식 | `"requiredPermissions": { "network": { "domains": [...] } }` | UXP manifest v5 문서 |
| ws://localhost + 포트 예시가 문서에 있나? | **없음** → 직접 테스트 | 〃 |
| 선례는? | adb-mcp 는 `"domains": "all"` + socket.io | adb-mcp `uxp/ps/manifest.json` |
| MCP SDK 버전 | `@modelcontextprotocol/sdk` 1.32.2 는 **v1 유지보수 라인**. 최신 안정판은 v2 (`@modelcontextprotocol/server` 2.4.0) | 패키지 README |

**결정:** 명세대로 v1(`@modelcontextprotocol/sdk`)을 쓴다. Claude Desktop 호환이 검증돼 있고 버그·보안 수정이 계속된다.
v2 전환은 2단계(두뇌 직접 만들기) 때 검토. 플러그인은 socket.io 없이 **UXP 내장 WebSocket** 사용.

## 만든 것

### mcp-server (TypeScript)
| 파일 | 역할 |
|---|---|
| `src/index.ts` | MCP 서버 진입점. `ps_status` 도구 등록, stdio 로 Claude 와 대화 |
| `src/bridge.ts` | WebSocket 서버 (`127.0.0.1` 전용). 요청마다 `id`, 120초 타임아웃, 끊기면 대기 중 요청 즉시 실패 |
| `src/config.ts` + `config.json` | 포트(8765), 타임아웃 설정 |
| `scripts/selftest.mjs` | 포토샵 없이 점검: 도구 목록 → 미연결 안내 → **가짜 플러그인**으로 왕복 |

메시지 형식:
```
서버 → 플러그인: { "id": 1, "command": "status", "params": {} }
플러그인 → 서버: { "id": 1, "ok": true, "result": {...} }   또는   { "id": 1, "ok": false, "error": "..." }
```

⚠️ **stdio MCP 서버에서는 `console.log` 금지.** stdout 이 Claude 와의 대화 통로라서 섞이면 통신이 깨진다. 로그는 `console.error`(stderr).

### ps-plugin (UXP)
| 파일 | 역할 |
|---|---|
| `manifest.json` | 패널 1개, network 권한 |
| `index.html` | 상태 ●, 연결/끊기 버튼, 로그 |
| `main.js` | 접속, `handlers` 표(허용된 명령만 실행), 실패도 같은 `id` 로 응답 |

## 테스트 과정

1. `npm run build` → 에러 없음
2. `node scripts/selftest.mjs` → ① 도구 목록 `ps_status` ② 미연결 안내 문구 ③ 가짜 플러그인 왕복 ✅
3. `npm run inspector` → 브라우저 Inspector → Tools → `ps_status` → **Execute Tool** → `connected: false` + 안내 ✅
4. UXP Developer Tool → Add Plugin → Load → 패널 **연결** → 실패 (아래 문제 1)
5. 해결 후 Execute Tool → 실제 포토샵 정보 반환 ✅

최종 결과:
```json
{
  "connected": true,
  "photoshopVersion": "28.0.0",
  "documentCount": 3,
  "activeDocumentId": 94,
  "documents": [
    { "id": 59, "name": "Untitled-1", "width": 1024, "height": 1024, "resolution": 72, "layerCount": 3 },
    { "id": 77, "name": "Untitled-2", "width": 1024, "height": 1024, "resolution": 72, "layerCount": 1 },
    { "id": 94, "name": "Untitled-3", "width": 1024, "height": 1024, "resolution": 72, "layerCount": 3 }
```

## 막혔던 문제와 해결

### 문제 1: `Permission denied to the url ws://127.0.0.1:8765. Manifest entry not found.`
| 시도 | `network.domains` | 결과 |
|---|---|---|
| 1 | `["ws://127.0.0.1:8765"]` | ❌ 같은 에러 |
| 2 | `["ws://127.0.0.1:8765", "ws://127.0.0.1", "ws://localhost:8765", "ws://localhost"]` | ❌ 같은 에러 (단, manifest 가 다시 읽혔는지 불확실) |
| 3 | `"all"` | ✅ 연결 |

- **교훈:** manifest 는 플러그인을 **Load 할 때만** 읽힌다. 바꾼 뒤엔 Reload 가 아니라 **Unload → Load**. 확인용으로 `main.js` 시작 시 "빌드 N" 을 로그에 찍게 했다.
- `"all"` 이어도 위험이 작은 이유: 플러그인 코드의 접속 주소는 `ws://127.0.0.1:8765` 하나로 고정, 임의 코드 실행 기능 없음.
- **할 일 (4단계):** 빌드 번호로 재로드를 확인하면서 좁힌 형식을 한 번 더 검증.

### 문제 2: `photoshopVersion` 이 결과에 없음
- `app.version` 이 PS 28 에서 `null`/`undefined` → JSON 에서 항목이 사라짐.
- 둘 다 찍어 비교: `require("uxp").host` → `"Photoshop 28.0.0"`, `app.version` → `null`.
- **해결:** `require("uxp").host.version` 사용.

### 참고: Inspector 의 `resources/list`, `prompts/list` ERROR
오류 아님. Inspector 가 "자료/프롬프트도 있나요?" 물어본 것이고, 우리 서버는 도구(tools)만 제공한다.

## 전체 구조에서의 역할
"두뇌 ↔ 관절 ↔ 손가락" 사이의 **신경**을 연결했다. 이제 MCP 서버가 `send("명령", 값)` 하면 플러그인의 `handlers` 에서 실행되고 결과가 돌아온다.
3단계는 `handlers` 에 1단계에서 검증한 batchPlay 명령을 넣고, MCP 서버에 도구를 등록하는 작업이다.
