# 5단계: Claude Desktop 연결과 테스트

> 날짜: 2026-11-12 · 결과: ✅ **완료** (Claude Desktop 이 스스로 도구를 골라 캔버스 생성 → 이미지 생성 → 실패 판단 → 재시도까지 수행)

## 무엇을, 왜
지금까지는 사람이 Inspector 에서 도구를 직접 눌렀다. 이번엔 **두뇌(Claude Desktop)** 를 연결해,
말로 부탁하면 Claude 가 **어떤 도구를 어떤 순서로 쓸지 스스로 판단**하는지 확인했다.
3단계에서 쓴 도구 설명(description)이 실제로 제 역할을 하는지 보는 시험이기도 했다.

**교훈:** 경로를 추측하지 말고 **Claude Desktop → 설정 → 개발자 → [구성 편집]** 버튼이 여는 파일을 쓴다.
(사용자가 직접 찾아 줬다.)

기존 내용(`coworkUserFilesPath`, `preferences`)은 그대로 두고 `mcpServers` 만 추가. 수정 전 원본은 `.backup-before-photoshop-agent` 로 백업.
```json
{
  "...기존 내용...": "그대로",
  "mcpServers": {
    "photoshop-agent": {
      "command": "C:/Program Files/nodejs/node.exe",
      "args": ["D:/photoshop-agent/mcp-server/dist/index.js"]
    }
  }
}
```
- 경로는 `/` 로 썼다. 처음엔 PowerShell → Node 로 넘기면서 `\\` 가 두 배(`\\\\`)로 들어가는 실수가 있었다.

### 시나리오 3 — 로그로 본 실제 호출 순서 (에이전트 루프)
```
ps_create_document  ✅ 1920×1080          ← 행동: 크기 지정 → 새 캔버스
ps_generate_image   ❌ 0.9초 "생성 실패"   ← 관찰: 새 레이어 없음
ps_status           ✅                      ← 판단 후 추가 관찰: 상태 재확인
ps_generate_image   ❌ modal state          ← 판단: "포토샵에 창이 떠 있다 → 사용자에게 닫아 달라"
   (사람: 원인 조사 → 표준 모델로 재녹화 → 플러그인 빌드 12)
ps_generate_image   ✅ 16.2초, 새 레이어    ← 행동 → 관찰(미리보기) → 결과 보고
```

### 시나리오 2 — Claude 가 스스로 프롬프트를 고쳐 재시도
```
ps_status → ps_create_document → ps_generate_image ❌(생성 실패) → [판단: 표현 수정] → ps_generate_image ✅
```
사람 개입 없이 "Eiffel Tower" → "tall iron lattice tower" 등으로 바꿔 다시 시도했고, 바꾼 내용과 사용 횟수(2/10)를 정직하게 보고했다.

| 에이전트 루프 | Claude 의 실제 행동 |
|---|---|
| 관찰 | 작업 전 `ps_status`, 실패 후 `ps_list_layers` / `ps_status` 로 재확인 |
| 생각·판단 | 2.2초·`newLayers: []` 를 보고 "이상하다" / "창이 떠 있다" / "표현 때문일 수 있다" |
| 행동 | 새 캔버스, 프롬프트 수정 후 재생성 |
| 관찰(이미지) | 미리보기를 보고 "갑옷 틈새 빛, 에펠탑, 행인" 을 확인해 보고 |

## 막혔던 문제와 해결

### 1. Claude Desktop 이 서버를 **2개** 실행 → 두 번째가 포트를 못 잡음 (EADDRINUSE)
```
pid 12624  01:00:59  (부모 claude.exe)  ← 8765 를 잡음, 플러그인도 여기 연결
pid 26128  01:01:00  (부모 claude.exe)  ← 포트 못 잡음. 그런데 대화는 이쪽과 진행
```
- 서버 개수는 우리가 정할 수 없다 → **여러 개 떠도 동작하게** 설계 변경.
- **중계소(hub) / relay:** 포트를 잡은 서버가 중계소, 못 잡은 서버는 중계소에 relay 로 붙어 명령을 대신 전달.
  중계소가 꺼지면 relay 가 포트를 넘겨받는다. `ps_status` 에 `serverRole` 표시.
- 플러그인: "연결"을 한 번 누르면 끊겨도 **2초마다 자동 재연결**.
- 자동 테스트 ⑩(서버 2개 동시) ⑪(중계소 종료 시 넘겨받기) 추가.

### 2. 생성이 실패했는데 "성공" 으로 보고 (거짓 성공)
- 포토샵이 2.2초 만에 **오류 없이** 끝내고 레이어만 안 생김 → 플러그인은 "오류 없으면 성공"으로 판단해 기존 그림을 그럴듯한 이름으로 저장까지 함.
- Claude 가 시간·`newLayers: []`·`ps_list_layers` 로 스스로 알아챔.
- **해결:** "새 레이어가 생겨야 성공" 으로 판정. 실패 시 원인 후보와 "포토샵 화면부터 확인" 안내를 돌려준다.

### 3. 크기를 지정했는데 열린 문서(1024)에 그대로 생성
- 도구 설명이 "열린 문서가 **없으면** 새로 만든다" 였기 때문.
- **해결:** "새 그림이거나 크기를 지정했으면, 다른 문서가 열려 있어도 먼저 새 캔버스" 로 설명 수정 → 이후 `ps_create_document` 를 먼저 호출.

### 4. ★ 생성이 계속 막힘 — 원인은 **👑 프리미엄 모델**
- 포토샵에 **"Add credits to unlock more creative AI"** 창. 그런데 계정의 **표준 크레딧은 999/1000** 으로 거의 그대로.
- 모델 목록: **Firefly Image 5 👑(프리미엄)** / **Firefly Image 3 (표준)**.
- 1단계 녹화 때 기본 모델이 Image 5 라서 `serviceVersion: "firefly_image_5"` — **채우기까지** 프리미엄이었다.
  생성이 프리미엄 "무료 체험" 횟수에서 빠졌고, 바닥나자 구매 창이 떠 모든 명령이 막혔다(`host is in a modal state`).
- 앞서 "콘텐츠 정책 거절" 로 본 실패 중 일부도 실제로는 이 한도였을 수 있다. (실패 메시지가 콘텐츠 정책만 의심하게 써 있던 것도 문제)
- **해결 (추측 금지 원칙대로):** 표준 모델을 고른 상태로 **다시 녹화** → `experiments/02-recorded-gen-std.js`

  | | 이미지 생성 | 생성형 채우기 |
  |---|---|---|
  | 이전 (👑) | `firefly_image_5` | `firefly_image_5` |
  | **지금 (표준)** | **`clio3`** (Firefly Image 3) | **`me_md`** |

  녹화본에 새로 생긴 `serviceOptionsList` 항목(파트너 모델 칸)과 `clio` 필드 3개도 그대로 반영. 모델 이름은 `firefly.js` 의 `MODEL` 한 곳에.
- 실패 메시지에 "크레딧 구매 창" 원인 추가, `host is in a modal state` 는 "포토샵 창을 닫아 달라" 는 한국어 안내로 변환.

### 5. 새 문서 만들기가 즉시 실패 (`Failed to create new document with given parameters`)
- 원인은 4번의 구매 창(모달) 으로 보인다. DOM 오류가 너무 모호해서,
  실패 시 녹화된 batchPlay `make` 로 재시도하고 그래도 실패하면 **포토샵의 자세한 오류**를 돌려주도록 했다(결과에 `via` 표시).

## 전체 구조에서의 역할
**두뇌가 연결됐다.** Claude Desktop 이 도구 설명만 보고 순서를 정하고, 결과 이미지를 보고 판단하고, 실패하면 고쳐서 다시 시도한다.
이번 단계의 문제들(서버 중복 실행, 거짓 성공, 모달 창, 프리미엄 모델)은 모두 **"손" 쪽**에서 고쳤으므로,
다음에 두뇌를 직접 만들어도 그대로 혜택을 받는다.
