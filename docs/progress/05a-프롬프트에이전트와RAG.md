# 5+단계: 프롬프트 에이전트 3역할 + 지식 창고(RAG)

> 날짜: 2026-11-12 · 결과: ✅ **완료** (자동 테스트 25개, Claude Desktop 실제 테스트 2개 통과)

## 무엇을, 왜
5단계를 하면서 실제로 막혔던 지점을 자동화했다.
- 한국어 요청을 Firefly 가 잘 알아듣는 **영어 프롬프트**로 옮기는 일
- 캐릭터 이름·건축물 이름 등으로 **거절**당한 뒤 고쳐 쓰는 일
- 실패 원인(크레딧 창 / 모달 / 콘텐츠 정책)을 **헷갈려** 엉뚱하게 대응한 일

## 설계 결정

### 어디서 돌리나 → Claude Desktop 이 판단, MCP 서버는 지식·순서 제공
| 선택지 | 결정 |
|---|---|
| **Claude Desktop 이 수행** | ✅ 채택. API 키·추가 비용 없음, 바로 테스트 가능 |
| MCP 서버 안에서 Claude API 로 서브 에이전트 | 2단계(두뇌 직접 만들기)에서 검토 |

지식 창고(`knowledge/`)와 검색 코드(`knowledge.ts`)는 **2단계에서도 그대로 재사용**한다.

### 요청 중 만들지 않기로 한 것: 필터 우회
"어도비가 거절할 내용을 교묘하게 바꿔 통과시키는 기능"은 만들지 않았다.
같은 대상·장면을 표현만 숨겨 얻는 것은 Adobe 의 안전·저작권 필터 우회이고, 이용 약관 위반·계정 제재·결과물의 법적 위험으로 이어진다.
**대신 "내용을 정직하게 바꾸는" 사전 점검**을 만들었다.

| 하지 않음 (우회) | 함 (정직한 재작성) |
|---|---|
| 철자·암시로 **같은 캐릭터**를 그리게 함 | 이름·고유 디자인을 빼고 **오리지널 캐릭터**를 새로 디자인 |
| 선정적 장면을 돌려 말해 통과 | **수위를 낮춘 다른 장면** 제안 |
| 몰래 바꿈 | **무엇을 왜 바꿨는지 생성 전에 알리고 확인** |

## 구조
```
사용자 요청 (한국어)
   │
   ▼
① 프롬프트 작가   ── ps_prompt_guide ── 📚 knowledge/prompt-guide.md + logs 비슷한 사례
   ▼
② 사전 점검       ── ps_prompt_guide(draft) ── 📚 policy-rewrite.md + 과거 "실패→성공" 표현 경고
   ▼               → 바꿀 게 있으면 생성 전에 사용자 확인
ps_create_document → ps_generate_image
   │ 실패
   ▼
③ 실패 분석       ── 오류에 [실패 분석] 자동 첨부 ── 📚 failure-causes.md + 비슷한 "실패→성공" 사례
```
- 순서는 MCP 서버 **instructions**(작업 순서 안내문)로 Claude 에게 전달 — 서버 연결 시 Claude 가 읽는다.

## 만든 것

| 파일 | 역할 |
|---|---|
| `knowledge/prompt-guide.md` | 영어 프롬프트 구조(화풍→주인공→동작→장소→조명→카메라→품질), 요령, 이 프로젝트 사례 |
| `knowledge/policy-rewrite.md` | **절대 하지 않는 것**(우회), 거절되기 쉬운 요소별 정직한 대안, 사용자에게 알리는 형식 |
| `knowledge/failure-causes.md` | 원인별 **신호**와 대응 (창/크레딧/정책/로그인/시간 초과/상한/미연결), "화면 확인 먼저" 원칙 |
| `mcp-server/src/knowledge.ts` | RAG: 문서 읽기, logs 에서 생성 사례 추출, **실패→성공 짝** 찾기, 단어 겹침 검색, 초안 위험 표현 점검 |
| `mcp-server/src/index.ts` | `ps_prompt_guide` 도구, 생성 실패 시 `withFailureHelp` 로 [실패 분석] 첨부, `instructions` |
| `ps-plugin/main.js` (빌드 13) | 생성 결과·실패에 사용 **모델** 기록 → 크레딧 한도 시기의 실패와 구분 (RAG 데이터 품질) |

### RAG 가 실제 기록에서 찾은 것
```
생성 기록 7건 (성공 4 / 실패 3), 실패→성공 짝 2개
- ❌→✅ 뺀 단어: mythical, paris, eiffel, ember, cracks, tattered  /  더한 단어: … tall, iron, lattice …
  (실패 원인 불확실: 크레딧 한도 시기와 겹침)   ← 모델 기록이 없던 시기라 정직하게 표시
초안 "a giant walking near the Eiffel Tower" → ⚠️ eiffel, paris 경고 + 대신 쓰인 표현 제시
```

## 알게 된 것
- 도구 설명보다 **instructions(작업 순서)** 가 "먼저 가이드를 보고 → 점검 → 생성" 같은 **순서**를 지키게 하는 데 효과적이었다.
- 기록(logs)이 곧 RAG 재료가 된다. 단, **데이터 품질**이 중요 — 모델 정보가 없던 시기의 실패는 원인을 단정할 수 없어 "불확실"로 표시.
- 단어 겹침 검색은 단순하지만 지금 규모(수십 건)에는 충분. 사례가 많아지면 2단계에서 임베딩 검색으로.

## 전체 구조에서의 역할
"손"에 **요령과 경험**을 붙였다. 두뇌(Claude)가 같은 실수를 반복하지 않도록, 지식 문서와 실제 기록에서 근거를 찾아 판단하게 한다.
2단계에서 두뇌를 직접 만들면 ①②③ 을 각각 **진짜 서브 에이전트**로 분리하고, 지금의 지식 창고와 검색 코드를 그대로 연결한다.
