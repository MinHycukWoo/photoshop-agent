# 3단계: 핵심 도구 만들기

> 날짜: 2026-11-12 · 결과: ✅ **통과** (도구 6개 모두 실제 포토샵에서 동작, 결과 이미지를 MCP image content 로 반환)

## 무엇을, 왜
2단계 통로 위에 Claude가 실제로 쓸 도구를 얹었다. 핵심은 **결과 이미지를 Claude가 직접 보게** 돌려주는 것.

### 왜 이미지를 돌려주는 게 핵심인가 — 에이전트 루프
```
생각: "고양이를 오른쪽 보게"  →  행동: ps_generate_image
   ↑                                      ↓
판단: "왼쪽을 보네, 프롬프트 수정"  ←  관찰: 결과 이미지 👀
```
글자("생성 완료")만 돌려주면 **관찰** 단계가 없어 Claude는 결과가 요청과 맞는지 모른다.
이미지를 돌려주면 생각 → 행동 → 관찰 → 판단 고리가 닫혀 스스로 다시 시도할 수 있다.

## 먼저 확인한 것

| 질문 | 확인 결과 | 결정 |
|---|---|---|
| 문서 생성 | 공식 DOM `app.documents.add({ width, height, resolution, name })` (기본 RGB·흰색) | DOM 사용 (녹화 불필요) |
| 레이어 정보 | `Layer`: `id, name, kind, visible, opacity, bounds{left,top,right,bottom}, layers`(그룹) | DOM 사용 |
| PNG 저장 | `document.saveAs.png(file: File, options?, asCopy)` — **File 객체**가 필요 | DOM 사용 |
| `D:\...` 같은 임의 경로에 파일 쓰기 | `file:` URL 의 **Windows 형식이 문서에 없음**, 권한 `fullAccess` 필요 | ❌ 쓰지 않음 → 아래 설계 |

### 설계: 파일은 서버가 저장한다
```
플러그인: 임시 폴더(권한 불필요)에 saveAs.png(사본) → 바이트를 base64 로 WebSocket 전송
서버:     output/ 에 저장 (파일 이름 정리 + 경로 검사) → sharp 로 768px JPEG 미리보기 → Claude 에게 반환
```
- 플러그인에 파일 쓰기 권한을 주지 않아도 된다.
- "output 밖으로 저장 금지" 검사를 **서버 한 곳**에서 한다 (4단계 안전장치와 연결).

## 만든 것

### 도구 (mcp-server/src/index.ts)

| 도구 | 하는 일 | 크레딧 |
|---|---|---|
| `ps_status` | 연결·버전·문서 목록 | - |
| `ps_create_document` | 새 캔버스 (64~4096px, 이름) | - |
| `ps_generate_image` | 활성 문서 전체 이미지 생성 → 새 레이어 → 저장 + **이미지 반환** | ⚠️ 1 |
| `ps_generative_fill` | 사각형 영역 채우기 → 마스크 레이어 → 저장 + **이미지 반환** | ⚠️ 1 |
| `ps_list_layers` | 레이어 목록 (위에서부터) | - |
| `ps_export_png` | 보이는 모습 그대로 PNG 저장 + **이미지 반환** | - |

각 `description` 에 **언제 쓰는지 / 언제 쓰지 않는지**, 크레딧 사용, 걸리는 시간을 적었다.
(예: "그림 일부만 바꾸려면 ps_generate_image 대신 ps_generative_fill", "생성 도구 직후 ps_export_png 를 다시 부를 필요 없음")

### 파일
| 파일 | 역할 |
|---|---|
| `ps-plugin/firefly.js` | 1단계에서 녹화로 확인한 batchPlay 명령 모음. 엔진 설정(`firefly_image_5` 등)을 한 곳에 |
| `ps-plugin/main.js` | 명령 처리기 6개. 생성 전후 레이어 id 비교로 **새 레이어** 찾기, 생성 후 선택 해제 |
| `mcp-server/src/output.ts` | PNG 저장(파일 이름 정리, output 밖 차단), 미리보기 생성 |
| `mcp-server/src/logger.ts` | **모든 도구 호출 기록** (아래) |
| `mcp-server/scripts/selftest.mjs` | 포토샵 없이 9개 항목 자동 점검 |

### 호출 기록 (원래 4단계 항목을 앞당김)
MCP Inspector 는 도구를 바꿀 때마다 이전 입력·결과가 사라진다. → **서버가 직접 기록**하게 했다. 어떤 클라이언트에서 불러도 남는다.

| 파일 | 내용 |
|---|---|
| `logs/YYYY-MM-DD.md` | 사람용: 시간, 도구, 입력, 결과, 걸린 시간, **결과 이미지** (VS Code `Ctrl+Shift+V`) |
| `logs/YYYY-MM-DD.jsonl` | 프로그램용: 한 줄 = 호출 1번 (두뇌 단계 참고 자료) |

## 알게 된 것

| 관찰 | 의미 |
|---|---|
| 채우기 결과 레이어 영역이 (583,483)-(1017,967) — 요청보다 **사방 ~17px 넓음** | 포토샵이 경계를 자연스럽게 섞으려고 영역을 조금 넓힌다. 정상 |
| 채우기 42초 | 타임아웃 120초로 충분. 도구 설명에 "20~40초" 안내 |
| PNG 원본 1.7MB → 미리보기 JPEG 768px | 대화 용량을 줄이면서 Claude 가 판단하기엔 충분 |
| Inspector 를 켜 둔 채 자동 테스트 → 포트 8765 충돌로 실패 | 테스트는 **전용 포트 18765** + 임시 로그 폴더 사용 (`PS_AGENT_PORT`, `PS_AGENT_LOGS_DIR` 환경 변수) |
| `../../evil` 이 처음엔 이름이 통째로 `image` 가 됨 | 확장자 제거 규칙이 너무 넓었음 → 진짜 확장자만 제거 |

## 전체 구조에서의 역할
"손"이 완성됐다. Claude 는 이제 캔버스 만들기 → 생성 → **결과 보기** → 부분 수정 → 저장을 스스로 조합할 수 있다.
남은 것은 이 손에 **안전장치**(생성 횟수 상한 등, 4단계)를 달고, 진짜 두뇌인 **Claude Desktop 에 연결**(5단계)하는 일이다.
