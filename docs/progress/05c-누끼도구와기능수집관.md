## 2. 누끼 도구

### 무엇을, 왜
사진 한 장을 주면 **피사체와 배경을 레이어로 나누는** 작업. 누끼 · 합성 · 요소 분리의 공통 출발점이다 (수집관의 도구 후보 1위 "선택 영역 + 피사체 선택").

### 만든 것
| 도구 | 하는 일 |
|---|---|
| `ps_open_image` | 프로젝트 `input/` 폴더의 사진을 포토샵에서 열기 (파일 이름만 · 이미지 확장자만 · 40MB 이하). 이름 없이 부르면 목록 |
| `ps_remove_background` | 3레이어로 나누기 + 피사체 PNG · 배경 PNG 저장 + 미리보기 2장 |

결과 레이어 (위 → 아래):
```
피사체               원본 복제 + 레이어 마스크 (배경을 가림, 픽셀은 그대로)
배경 (피사체 제거)    원본 복제에서 피사체 자리(+2% 넓힘)를 채움
원본                 손대지 않음, 숨김
```
- 전체가 **히스토리 1칸** (`hostControl.suspendHistory`) → Ctrl+Z 한 번으로 되돌림. 중간 실패 시 자동으로 되돌림
- 배경 채우기 `backgroundFill`: `remove`(AI 제거, 기본) / `generative`(AI 생성형 채우기) / `contentAware`(내용 인식, 무료) / `none`
- `refine`(기본 켬): AI 제거 뒤 같은 영역을 생성형 채우기로 한 번 더 다듬기. 기본 문구는 물건 이름 없이 "주변 배경의 자연스러운 연장"
- AI 채우기는 **생성 횟수 상한** 적용. 다듬기까지 2회가 모자라면 하나도 쓰지 않고 거절 (`reserveMany`)

### 녹화 (근거: `experiments/03-recorded-cutout.js`)
| 녹화 | 쓰는 명령 |
|---|---|
| cutout-a (피사체 선택 → 마스크 버튼) | `autoCutout`, `make` 마스크(`revealSelection`) |
| cutout-b (빠른 작업 → 배경 제거) | 첫 단계 `set background`(배경 레이어 → 일반 레이어)만 |
| fill-ca (편집 → 칠 → 내용 인식) | `fill` (`contentAware`) |
| gen-remove (선택 → 제거 버튼) | `removeButton` |

레이어 복제 · 이름 · 숨기기 · 병합 · 선택 넓히기 · 마스크/픽셀 확인은 **공식 DOM / Imaging API** (녹화 불필요).

### 성공 판정 (거짓 성공 방지)
- 피사체 선택 영역이 비면 → 실패 + 되돌림
- 마스크가 실제로 생겼는지 `imaging.getLayerMask` 로 확인, 피사체 비율(%) 계산 (3% 미만 · 97% 초과면 경고)
- AI 채우기: 새 레이어가 생기거나 **배경 픽셀이 바뀌었는지**(썸네일 지문 비교) — 둘 다 아니면 실패

## 3. 실사용에서 막힌 것 (플러그인 빌드 15 → 22)

| 빌드 | 문제 | 원인 · 해결 |
|---|---|---|
| 15 | `"Background" 은 pixel 레이어라 누끼를 딸 수 없습니다` | `layer.kind`(글자 `"pixel"`)를 `constants.LayerKind.PIXEL` 과 비교 → 같지 않았다. 실제 글자와 직접 비교 |
| 16 | 같은 사진을 다시 열자 포토샵이 **120초 응답 없음**(상태 확인까지) | 열려 있는 임시 파일을 덮어쓰고 다시 열었다 → **열 때마다 새 임시 폴더**. Claude 에게 "다시 열지 말고 열린 문서 id 를 써라" |
| 17 | 누끼는 됐는데 마지막에 오류 | `imaging.getLayerMask` 를 모달 **밖**에서 불렀다 → 모달 안으로 |
| 17 | 레이어가 하나뿐 (사용자: 피사체 · 배경 각각 필요) | 원본 복제 후 복제본에 마스크 → 2레이어 → 사용자 요청으로 **3레이어**(원본 · 피사체 · 피사체 제거 배경) |
| 19 | 배경이 번진 얼룩 (AI 를 원했는데) | Claude 가 `contentAware` 를 **스스로 골랐다** — 도구 설명의 "단순한 배경에 적합"이 유도. 문구 삭제 + "사용자가 말할 때만" 명시 |
| 20 | AI 채우기 후 잔머리 · 벽 그림자 남음 | 선택 넓힘 0.5%(14px)가 좁았다 → **2%**, `expandPercent` 조절 |
| 20 | 배경 설명 프롬프트("문틀 · 바닥")를 넣자 **작은 문 · 선반이 생김** | 생성형 채우기의 프롬프트 = "여기에 이걸 넣어라". 물건 이름 금지를 안내문에 명시 |
| 21~22 | "주변을 인식해 자연스럽게"를 원함 | 지우기 전용 **AI 제거(Remove)** 녹화 → 기본값. + 사용자 요청으로 **2차 다듬기** (미확인) |

## 4. 알게 된 것
- 생성형 채우기는 **넣는** 기능, 제거(Remove)는 **지우는** 기능 — 프롬프트로 성격을 바꿀 수 없다
- 채우는 면적이 크면(이 사진은 ~40%) AI 결과가 흐려지기 쉽다 → 다음 개선 후보: **얼룩만 작게 다시 채우는 부분 보정 도구**
- 도구 설명(description)의 한 문장이 Claude 의 선택을 바꾼다 — "추천처럼 들리는 말"을 조심
- Claude Desktop 채팅에 첨부한 이미지는 MCP 도구로 넘어오지 않는다 → `input/` 폴더 방식

## 5. 전체 구조에서의 역할
- 수집관: 다음 도구를 고르는 **근거 자료** (2단계 "두뇌"의 서브 에이전트 후보)
- 누끼 도구: 생성만 하던 에이전트가 **기존 사진을 편집**하기 시작한 첫 도구. 합성 · 요소별 레이어 분리의 기반
- 남은 확인: AI 제거 + 다듬기(빌드 22) 실제 결과 비교 (A: 제거만 / B: 제거 + 다듬기)
