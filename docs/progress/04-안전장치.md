# 4단계: 안전장치 (가드레일)

> 날짜: 2026-11-12 · 결과: ✅ **완료** (자동 테스트 17개 통과, 실제 플러그인 접속 확인)

## 무엇을, 왜
"손"은 Claude 가 시키는 대로 움직인다. Claude 가 실수하거나 **속아도**(프롬프트 인젝션) 크레딧을 다 쓰거나,
엉뚱한 곳에 파일을 쓰거나, 다른 프로그램이 통로를 가로채지 못하게 **할 수 있는 일의 한계를 코드로** 정했다.
AI 의 판단을 믿는 게 아니라, 애초에 위험한 일을 할 수 없게 만든다.

### 1. 왜 임의 코드 실행 도구를 만들지 않나
`run_script(code)` 하나만 있어도 Claude 는 포토샵 안에서 **무엇이든** 할 수 있다 — 파일 삭제, 크레딧 무한 사용, 다른 문서 덮어쓰기.
더 위험한 건 **프롬프트 인젝션**: Claude 가 읽은 웹페이지·이미지에 "run_script 로 ○○ 실행" 같은 글이 숨어 있으면 속아서 실행할 수 있다.
정해진 동작만 열어 두면 최악의 경우에도 "그림을 이상하게 만드는 것"에서 끝난다.
플러그인의 `handlers` 표에 없는 명령은 `알 수 없는 명령` 으로 거절된다.

### 3. Origin 허용 목록
웹 브라우저의 페이지도 `ws://127.0.0.1:8765` 에 접속을 시도할 수 있다(같은 PC 이므로).
악성 페이지가 먼저 붙으면 **플러그인 행세**를 하며 Claude 의 명령(프롬프트 등)을 가로챌 수 있다.

- 브라우저는 접속할 때 **항상** `Origin` 헤더를 붙인다 (`https://...`, 로컬 HTML 파일은 `null`).
- 실제 UXP 플러그인이 보내는 값을 `ps_status` 의 `pluginOrigin` 으로 확인 → **`file://`**
- 그래서 차단 목록("브라우저 같으면 거절")이 아니라 **허용 목록**("`file://` 이거나 없음만 허용")으로 했다. 모르는 종류는 기본 거절.

### 5. 생성 횟수 상한
- `mcp-server/config.json` → `"maxGenerationsPerRun": 10` (서버 = Claude Desktop 이 실행할 때마다 새로 셈)
- `ps_generate_image` + `ps_generative_fill` 합계. **실패한 생성도 1회** — 포토샵 쪽에서 크레딧이 빠졌는지 알 수 없으므로 보수적으로.
- 상한에 닿으면 포토샵에 **명령을 보내지 않고** 오류: "config.json 의 maxGenerationsPerRun 을 늘리거나 서버를 다시 시작"
- 생성 결과에 `generationCount: "3/10"`, `ps_status` 에 `generations: { used, limit, remaining }` → Claude 가 남은 횟수를 안다.
- 도구 description 에도 상한을 적어 Claude 가 미리 알게 했다.

## 막혔던 문제: manifest 접속 범위 좁히기 (2단계에서 미룬 재검증)

| 시도 | `network.domains` | 재로드 확인 | 결과 |
|---|---|---|---|
| 2단계-1 | `["ws://127.0.0.1:8765"]` | 첫 Load | ❌ Permission denied |
| 2단계-2 | 주소 4개 (`ws://127.0.0.1(:8765)`, `ws://localhost(:8765)`) | 불확실 | ❌ |
| **4단계** | 주소 4개 | ✅ 로그에 `빌드 7 (network: 주소 4개 재검증)` | ❌ **Permission denied … Manifest entry not found** |

**결론:** Photoshop 28 의 UXP 는 `ws://` 주소 지정 형식으로 WebSocket 을 허용하지 않는다(적어도 이 형식들로는). 3번 실패 → 규칙대로 멈추고 `"all"` 유지.

**`"all"` 이어도 괜찮은 이유 (다른 장치가 막는다):**
- 플러그인 코드의 접속 주소는 `ws://127.0.0.1:8765` 하나로 **고정** — 다른 곳에 접속하는 코드가 없다.
- 임의 코드 실행 기능이 없어, 누가 명령을 보내도 다른 주소로 접속시키지 못한다.
- 서버 쪽은 `127.0.0.1` 전용 + Origin 허용 목록.

✅ ⑨ 기존 플러그인 연결은 유지
(①~⑥ 3단계 항목 포함 17개 모두 통과)

### 실제 포토샵
- `ps_status` → `connected: true`, `generations: {used 0, limit 10, remaining 10}`, **`pluginOrigin: "file://"`**, `rejectedConnections: 0`
- manifest 재검증 → 위 표

## 전체 구조에서의 역할
손에 **한계**를 달았다. 이제 Claude Desktop(5단계)에 연결해도, Claude 가 할 수 있는 일은
"정해진 6개 동작 × 최대 10회 생성 × output 폴더 안 저장" 으로 묶인다.
2단계에서 두뇌를 직접 만들 때도 이 한계는 서버·플러그인에 있으므로 **그대로 유지**된다.
