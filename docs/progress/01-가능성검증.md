# 1단계: ★ 가능성 검증 — 생성형 AI를 batchPlay로 부를 수 있는가?

> 날짜: 2026-11-11 · Photoshop 28.0.0 · 결과: ✅ **통과** (이미지 생성 · 생성형 채우기 모두 가능)

## 무엇을, 왜
포토샵 생성형 AI를 **스크립트(batchPlay)로 호출할 수 있는지**가 이 프로젝트의 전제다. 안 되면 나머지가 의미 없다.
batchPlay 명령 형식은 추측하면 안 되므로, 포토샵이 직접 만들어 준 **진짜 명령**을 기준으로 삼았다.

## 한 일

### 1. 액션 녹화 → JavaScript로 복사
1. 액션 패널(`Alt+F9`)에서 세트 `ps-agent`, 액션 `gen-test` 를 만들고 녹화 시작
2. 새 문서 1024×1024 → **이미지 생성** (`a cat`) → 사각형 선택 → **생성형 채우기** (`red ball`)
3. 녹화 중지 → 액션 패널 메뉴 **Copy As JavaScript** (개발자 모드에서만 보임)

원본: [`experiments/00-recorded-gen-test.js`](../../experiments/00-recorded-gen-test.js) (수정 금지, 근거 자료)

| 단계 | batchPlay 명령 (`_obj`) |
|---|---|
| 새 문서 | `make` |
| 이미지 생성 | `syntheticTextToImage` |
| 사각형 선택 | `set` (`_property: "selection"`) |
| 생성형 채우기 | `syntheticFill` |

### 2. 녹화 코드 분석

**프롬프트가 들어가는 곳**
- 이미지 생성: 바깥 `prompt` 만. (안쪽 `gi_PROMPT` 는 녹화본에서 `""`)
- 생성형 채우기: 바깥 `prompt` **와** 안쪽 `gi_PROMPT` 두 곳 모두.

**바꿔도 되는 값 / 바꾸면 안 되는 값**

| 구분 | 값 | 이유 |
|---|---|---|
| ✅ 바꿔도 됨 | `prompt`, (채우기) `gi_PROMPT` | 우리가 넣을 내용 |
| ✅ 바꿔도 됨 | `width`, `height`, `resolution` | 캔버스 크기 |
| ✅ 바꿔도 됨 | 선택 영역 `top/left/bottom/right` (픽셀) | 채울 위치 |
| ⚠️ 빼야 함 | `documentID`, `layerID` | 녹화 당시 번호. `_target` 이 이미 "현재 문서"를 가리킴 |
| ❌ 그대로 | `serviceID: "clio"`, `serviceVersion: "firefly_image_5"`, `gi_MODE`(`ginp`/`tinp`), `workflowType`, `workflow_to_active_service_identifier_map` | 포토샵 내부 AI 엔진 설정. 포토샵 업데이트 시 바뀔 수 있음 → 코드 한 곳에 모아 관리 예정 |
| 🤔 미확인 | `gi_SEED: -1` | 아마 "매번 랜덤" |

### 3. 프롬프트만 바꿔 다시 실행
스크립트: [`experiments/01-gen-test.psjs`](../../experiments/01-gen-test.psjs)
— 녹화본에서 ① 프롬프트 변경 ② `documentID`/`layerID` 제거 ③ 결과 알림창 추가, 이 3가지만 바꿨다.

실행 방법: 포토샵 **파일 > 스크립트 > 찾아보기...** → `.psjs` 파일 선택.
(플러그인 없이 UXP 코드를 바로 실행하는 방법. 크레딧 2회 사용)

## 결과

```
✅ 성공
[새 문서] id 94
Background (id 1, pixel)

[이미지 생성] 9.8초
a cat sitting by a window, watercolor (id 2, smartObject)
Background (id 1, pixel)

[생성형 채우기] 34.5초
a small potted plant (id 3, smartObject)
a cat sitting by a window, watercolor (id 2, smartObject)
Background (id 1, pixel)
```

창가의 수채화 고양이 + 창틀 위 화분이 정상 생성됨.

## 알게 된 것 (→ 3단계 도구 설계에 반영)

| 관찰 | 의미 | 반영할 점 |
|---|---|---|
| `documentID`/`layerID` 없이도 동작 | "현재 문서" 기준으로 실행됨 | 도구는 활성 문서를 대상으로 동작 |
| 결과는 **프롬프트 이름의 새 Generative Layer** (smartObject), id 순차 증가 | 원본을 덮어쓰지 않고 레이어로 쌓임 | `ps_list_layers`로 추적 가능 |
| 채우기 레이어엔 **마스크**가 자동으로 붙음 | 선택 영역만 보이도록 잘림 | 좌표만 넘기면 됨 |
| 스크립트 실행 시 Variations **1/1** | 호출 1번 = 결과 1장 | 크레딧 계산이 단순 |
| 실행 중 크레딧 확인 창이 **뜨지 않음** | 스크립트가 크레딧을 바로 씀 | 4단계 **생성 횟수 상한** 필수 |
| 이미지 생성 ~10초, 채우기 ~35초 | 생각보다 오래 걸림 | 요청 타임아웃 120초 |
| 👁 끄면 결과가 안 보임 | 최종 결과물 = 보이는 레이어 합성 | `ps_export_png`는 보이는 모습 그대로 저장 |
| showAlert 아이콘이 성공에도 빨간 ❌ | Windows UXP 알림창의 기본 아이콘 | 무시해도 됨 |

## 전체 구조에서의 역할

```
[Claude Desktop] → [MCP 서버] → [UXP 플러그인] → ✅ syntheticTextToImage / syntheticFill
                                                     (이번에 검증)
```

맨 끝 "손가락이 실제로 움직일 수 있는가"를 확인했다. 이 명령 구조를 2~3단계에서 플러그인 안으로 옮기고,
프롬프트·크기 값만 MCP 서버에서 받아 오게 만든다.
