# 5++단계: 카메라·구도 RAG · 생성 흐름 바로잡기 · 프롬프트 정보 수집관

> 날짜: 2026-11-12 · 결과: ✅ **완료** (자동 테스트 31개 통과, Claude Desktop 에서 "생성 전 확인" 동작 확인)

## 1. 카메라·구도 RAG

### 무엇을, 왜
결과가 계속 **"가운데에 정면으로 차렷 자세"** 로 나왔다. Firefly 는 구도를 지정받지 못하면 무난한 기본 구도를 고른다.
→ 촬영 기법·구도 지식을 만들고, 사용자 말에서 원하는 기법을 찾아 프롬프트에 넣게 했다.

### 핵심 아이디어: 영상 기법을 정지 이미지로 옮기기
팬·틸트·오빗·트래킹·돌리·크레인·핸드헬드·돌리 줌·랙 포커스·롤은 **영상의 카메라 움직임**이다.
Firefly 는 정지 이미지를 만들므로 **그 움직임이 사진에 남기는 흔적**으로 표현한다.

| 영상 기법 | 정지 이미지 표현 |
|---|---|
| 팬 | 주인공 선명 + 배경 가로 잔상 |
| 트래킹 | 나란히 따라가는 시점 + 흐르는 바닥 |
| 돌리 줌 | 광각 원근 왜곡 정도로만 비슷 (솔직하게 안내) |
| 랙 포커스 | "옮겨 가는" 과정은 불가 → 초점 위치 하나를 정함 |

### 만든 것
- `knowledge/camera-composition.md`: **27개 기법** (카메라 움직임 11 · 앵글 5 · 샷 크기 3 · 사진 기법·렌즈 4 · 구도 규칙 3 · 동작 어휘) — 각 항목에 키워드 · 프롬프트 표현 · 효과 · 주의
- `knowledge.ts`: 문서를 기법별로 쪼개 **키워드가 요청에 들어 있는지**로 검색. 한국어 어미 변화(따라가**며**/따라가**는**)를 위해 마지막 글자를 뗀 어간으로도 비교
- 구도 언급이 없으면 성격이 다른 기본 3개(트래킹·로우 앵글·더치 앵글) + 역동성 재료 제시
- 역동성 공식: **동작(동사) + 카메라 기법 + 환경 반응**

## 2. 생성 흐름 바로잡기 (실제 실패에서 발견)

| 문제 | 해결 |
|---|---|
| 새 문서 만들기 실패("탭을 붙일 공간 없음", 문서 8개) → **다른 문서에 생성** | 생성·채우기에 **`documentId` 필수**. 플러그인이 그 문서를 골라 생성, 없으면 멈춤. 새 문서 실패 시 "다른 문서에 생성 말고 멈추라" + 열린 문서 수 안내 |
| 새 레이어가 **선택된 레이어 바로 위**에 생겨 기존 레이어에 가려짐 | 공식 DOM `Layer.move(맨 위 레이어, PLACEBEFORE)` 로 **맨 위로 이동** 후 확인. 확인 못 하면 성공 보고 안 함 (플러그인 빌드 14) |
| 가려진 채 저장 → 엉뚱한 미리보기 | 위 두 가지 + 저장도 같은 `documentId` 로 |
| 영어 프롬프트·구도 제안 없이 **바로 생성** | **사전 점검을 거친 프롬프트만 생성** — `ps_prompt_guide` 의 `draft` 로 점검받지 않은 문구는 서버가 거절(크레딧 0). 생성 전 **[영어 프롬프트 · 한국어 뜻 · 적용한 구도 · 다른 구도 2개 · 바꾼 점]** 을 보여 주고 확인받는 형식을 도구 결과와 instructions 에 명시 |

결과: Claude Desktop 이 생성 전에 프롬프트와 구도 선택지를 보여 주고 "어떻게 할지" 묻게 됐다.

## 3. 프롬프트 정보 수집관

### 무엇을, 왜
지식 창고가 내가 쓴 가이드와 이 PC 의 기록뿐이라 표현의 폭이 좁았다. **세상 사람들이 실제로 효과를 본 표현**을 모아 넓힌다.

### 설계 결정
| 항목 | 결정 |
|---|---|
| 무엇을 모으나 | 남의 프롬프트 **전문은 복사하지 않음**(판매되는 것도 있고 타인의 창작물). **패턴**(구조·짧은 표현 조각·원리)을 자기 말로 + **출처** |
| 빼는 것 | 실존 작가 이름으로 화풍 지정, 캐릭터·브랜드·실존 인물 이름, 필터 우회 요령 |
| 신뢰도 표시 | `[공식]` Adobe 자료 / `[커뮤니티]` 업체 블로그·갤러리에서 반복되는 관행(미검증) |
| 어디서 돌리나 | Claude Desktop(MCP)은 웹 검색 불가 → **Claude Code 스킬** `prompt-collector` 로 수집, 결과 문서를 `ps_prompt_guide` 가 RAG 로 읽음 |

```
[Claude Code: prompt-collector 스킬] ─ 웹 조사 ─▶ knowledge/prompt-patterns.md (출처·신뢰도)
[Claude Desktop] ─ ps_prompt_guide ─ 요청·영어 초안에 맞는 패턴만 골라 읽음 ◀┘
```

### 첫 수집 결과 (`knowledge/prompt-patterns.md`, 18개 패턴)
| 묶음 | 패턴 |
|---|---|
| A. 기본 원칙 | Adobe 공식 작성 원칙 [공식], 레이어 공식(주인공→스타일→구도→조명→수식어) |
| B. 사실감 | 조명은 한 가지 레시피로, 렌즈·심도, 일부러 넣는 불완전함(필름 그레인 등), 사진 장르 이름 |
| C. 역동성 | 멈춘 순간 vs 흐르는 속도, 패닝 공식, 동작은 몸의 자세로 구체적으로 |
| D. 장르별 | 제품 · 인물 · 풍경 · 음식 · 수채화 · 플랫 일러스트 · 판타지 시네마틱 · 사조·재료로 스타일 지정 [공식] |
| E. Firefly 전용 | 콘텐츠 유형·참조 이미지와 함께 쓰기 [공식] |

- 막힌 출처: Adobe 도움말 `helpx…/tips-and-tricks.html` 은 자동 접근 거부(403) → 검색 요약만 참고하고 기록에 남김.
- 검색 확인: "질주하는 고양이 기사, 실사풍" → 패닝 공식·멈춘 순간 vs 흐르는 속도·조명 레시피 / "화장품 병 광고 사진" → 제품 사진 / "수채화 느낌" → 수채화 일러스트

### 다시 수집하려면
Claude Code 에서 **"프롬프트 패턴 업데이트해 줘"** 또는 **"음식 사진 프롬프트 패턴 모아 줘"** → `.claude/skills/prompt-collector/SKILL.md` 절차대로 조사·정리·확인.

## 테스트 (자동 31개 통과) — 새 항목
```
✅ ⑭ '따라가며 · 질주' → 트래킹 · 팬 추천
✅ ⑭ 구도 언급 없음 → 기본 제안 + 역동성 재료
✅ ⑮ 점검 안 받은 프롬프트는 생성 거절
✅ ⑮ 거절된 생성은 횟수를 쓰지 않음
✅ ⑯ '화장품 광고' → 제품 사진 패턴 + 출처
✅ ⑯ 공식 작성 원칙 항상 포함
```

## 전체 구조에서의 역할
지식 창고가 세 겹이 됐다: **내가 정리한 규칙**(가이드·정책·실패 원인·구도) + **이 PC 의 경험**(logs) + **세상의 관행**(웹 수집 패턴).
2단계에서 두뇌를 직접 만들면 정보 수집관을 **주기적으로 도는 서브 에이전트**로 바꾸고(예: 매주 실패가 잦은 장르를 조사), 지금의 문서 형식과 검색 코드를 그대로 쓴다.
