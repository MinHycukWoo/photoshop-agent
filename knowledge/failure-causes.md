# 생성 실패 원인과 대응 (실패 분석 역할)

포토샵은 생성이 실패해도 **이유를 알려 주지 않는다.** 아래 "신호"로 원인을 좁힌다. (이 프로젝트에서 실제로 겪은 사례 기반)

| 원인 | 신호 | 대응 |
|---|---|---|
| **포토샵에 창이 열려 있음** (크레딧 구매 창, 경고, 대화상자) | 오류에 `modal state` / "창이 열려 있어", 새 문서 만들기도 즉시 실패 | 사용자에게 **포토샵 화면의 창을 닫아 달라고** 요청. 창 내용을 알려 달라고 하면 원인 파악에 도움. 재시도는 창을 닫은 뒤 |
| **크레딧·체험 횟수 부족** | 1초 안팎에 끝나고 새 레이어 없음 + 이후 `modal state` (구매 창) | 사용자에게 알림. 👑 프리미엄 모델을 쓰고 있지 않은지 확인 (`ps_status` 의 `generativeModels`). 프롬프트를 바꿔도 해결되지 않음 |
| **콘텐츠 정책 거절** (캐릭터·브랜드·실존 인물·선정성·폭력) | 1~3초에 끝나고 새 레이어 없음, **창은 뜨지 않음** | `policy-rewrite.md` 규칙대로 **내용을 정직하게 바꿔** 1번만 재시도하고, 바꾼 내용을 알림. 같은 실패가 반복되면 멈추고 사용자와 상의 |
| **로그인 만료** | 새 레이어 없음 + 포토샵에 로그인 관련 알림 | 사용자에게 포토샵/Creative Cloud 로그인 확인 요청 |
| **시간 초과** | "N초 안에 응답하지 않았습니다" | 포토샵이 바쁘거나 창이 떠 있음 → 화면 확인 요청 |
| **생성 횟수 상한** (이 서버의 안전장치) | "생성 횟수 상한" 오류 | 재시도하지 말고 사용자에게 알림 (config.json 의 maxGenerationsPerRun) |
| **플러그인 미연결** | "플러그인이 연결되어 있지 않습니다" | 포토샵 PS Agent 패널에서 "연결" 요청 |

## 원칙
- **먼저 화면 확인, 그다음 프롬프트 수정.** 창 때문에 막힌 것을 프롬프트 탓으로 오해하면 크레딧과 시간을 낭비한다.
  (5단계에서 실제로 프리미엄 한도를 콘텐츠 정책으로 오해했다)
- 재시도는 원인을 바꾼 경우에만 한다. 같은 프롬프트를 그대로 반복하지 않는다.
- 실패한 시도도 생성 횟수에 포함된다.
